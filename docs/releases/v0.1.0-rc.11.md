# v0.1.0-rc.11 — experimental macOS desktop candidate

Candidate source: `3ce3edbe0f91707af4b58aa83c3c8704684bb6c2`.
This historical candidate failed image qualification for
[#35](https://github.com/kreuzhofer/tofa-launcher/issues/35). It was not published.
The approved image workaround will be qualified in a separate rc12 candidate.

The candidate accepts compatible desktop versions above documented minimums,
handles the updated packaged engine and its temporary startup helper, and lets
each desktop conversation retain its selected Token Factory model. Eligible
Experimental models remain selectable. Desktop defaults do not change CLI model
or reasoning defaults. Missing assistant-message IDs are repaired at the request
boundary. For GLM 5.3, native `None` uses the provider's default thinking behavior
with an explicit terminal notice; native reasoning and answer channels remain
separate. The adapter does not strip response text or invent reasoning summaries.

## Limitations

- This remains experimental. GLM 5.3 Flash as a main and other unqualified choices
  retain Experimental labels; a successful short check does not promote them.
  Models missing compatible metadata are omitted with an explicit explanation.
- DeepSeek and GLM automatic naming are unsupported. Only the previously captured
  Kimi automatic-title contract has an auxiliary route; this run does not freshly
  qualify Kimi naming. A naming error is distinct from main-chat failure.
- Compaction and other unrecognized auxiliary requests remain unsupported. On
  recognized context compaction, the request fails before upstream inference with
  instructions to select sufficient context or start another conversation. Saved
  history is retained. Actual provider context limits are not stress-qualified.
  [Research #72](https://github.com/kreuzhofer/tofa-launcher/issues/72) tracks a
  compatible native compaction path; the current refusal does not establish a
  provider impossibility.
- Switching to a text-only model retains saved images but omits them from that
  model's input with a terminal notice. Switching back to an image-capable model
  restores their availability. Native-engine synthetic checks cover this and
  context-pressure refusal; they do not establish live image-model quality.
- GLM 5.3's native `None` label cannot disable thinking. The launcher announces
  provider-managed thinking once per affected launch. Other explicit efforts and
  other models are unchanged; CLI raw-reasoning visibility remains a native setting.
- Native and Token Factory providers do not migrate when a different provider's
  model is selected. Ordinary mode retains Token Factory history for reading;
  resume its inference through tofa. Catalog changes require a relaunch.
- Native deadlines, permissions and managed policy remain in force. Slow provider
  responses can still time out. Signing and notarization are not provided.

Earlier startup, missing-ID, reasoning and observer failures remain recorded in
the [adaptation checkpoint](desktop-minimum-version-2026-09-30.md) and
[reasoning investigation](../research/desktop-cli-reasoning-2026-09-30.md).
The separate two-platform CLI qualification in #23 is not completed by this work.
