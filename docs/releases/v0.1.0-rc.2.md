# v0.1.0-rc.2 — automatic-review request compatibility

Published on 2026-09-22 from commit
`176f09ce8a3d405e537283b299cd8d3c5150675f`. This candidate addresses
[#26](https://github.com/kreuzhofer/nebius-tofa-cli/issues/26); it does not establish
completion of the required real-machine qualification in #23.

## Change

For the observed Codex Guardian request with Kimi-K3, the adapter preserves the
reviewer tools, policy/action context and complete decision schema as explicit
final-answer instructions, while removing the non-strict output-decoding field
that Token Factory rejects alongside tools. Other text settings are retained.
The launcher announces this adaptation. Unsupported conflicting Kimi schema/tool
shapes fail explicitly rather than being silently weakened.

Codex still owns approval decisions and execution. Its existing JSON assessment
parser and failure-to-denial behavior are unchanged. The adapter does not produce
an allow decision, disable review, remove inspection tools, add retries or rewrite
responses. Codex may perform its own review attempts within its deadline.

## Diagnostic evidence — 2026-09-22

The maintainer reported a working Kanban app built through rc.1, but automatic
review failed for `npm install --no-audit --no-fund` and `npm run dev`; both commands
were run manually afterward.

The controlled diagnostic used installed `tofa v0.1.0-rc.1` (macOS ARM64 SHA-256
`9fb767d34b861298f3d5b97aff08f89392dbae75a2249c3d1c3fc3c09a21541f`) and
`codex-cli 0.155.1`. Synthetic main responses requested a harmless `printf` command
to trigger the actual reviewer. The reviewer request went through the real
launcher to Token Factory. Only request metadata, status and timing were saved.
These are not full real-machine qualification reports.

| Variant | Request | Observed response | Limit of evidence |
| --- | --- | --- | --- |
| Original | Three reviewer tools, `tool_choice: auto`, `text.format: json_schema`, `strict: false` | HTTP 400 after 165.7 seconds; known tools/constrained-decoding conflict | Confirms the backend rejection; Codex's review deadline had already expired |
| Diagnostic adaptation | Same tools/context; full schema appended to instructions; decoding format removed | HTTP 200 headers after 242.3 seconds | Codex had disconnected; no complete response or final assessment was observed |

An earlier ordinary live trace received HTTP 200 headers after 84.3 seconds and
was cut off during streaming by the diagnostic harness's original 90-second
request bound. That cutoff was a diagnostic limit, not a provider rejection.
The standalone tracing tool now defaults to 300 seconds per request and 600
seconds per session, with explicit overrides. Timeouts leave diagnosis incomplete.
See [tracing instructions](../codex-tracing.md).

## Independent Codex deadline

Codex 0.155.1 hardcodes a 90-second absolute automatic-review deadline, including
preparation, all review attempts and tool turns. Streaming activity does not reset
it. No supported configuration or model-catalog override was found in the pinned
source. Increasing trace or provider socket timeouts cannot extend this client
limit. Variable Token Factory latency can therefore still cause automatic reviews
to time out after the request-format fix.

The [deadline constant](https://github.com/openai/codex/blob/be2951ea34f0d295ed0becf97079f92fa5f6950e/codex-rs/ext/guardian-reviewer/src/lib.rs#L36),
[review deadline](https://github.com/openai/codex/blob/be2951ea34f0d295ed0becf97079f92fa5f6950e/codex-rs/ext/guardian-reviewer/src/review.rs#L57),
and [assessment parser](https://github.com/openai/codex/blob/be2951ea34f0d295ed0becf97079f92fa5f6950e/codex-rs/ext/guardian-reviewer/src/assessment.rs)
are pinned to Codex 0.155.1. For an immediate alternative, `/permissions` →
**Ask for Approval** selects human review where permitted by managed requirements.
This is an explicit user choice; the launcher does not switch review modes.

### macOS ARM64

Requires Python 3.9+, `curl`, authenticated `gh` and an installed Codex CLI.
In a new checkout:

```sh
gh repo clone kreuzhofer/nebius-tofa-cli tofa-qualification-rc2
cd tofa-qualification-rc2
git checkout --detach v0.1.0-rc.2
git rev-parse HEAD
python3 scripts/qualify_macos.py \
  --version v0.1.0-rc.2 \
  --output "$HOME/tofa-macos-rc2-$(date +%Y%m%d-%H%M%S).json"
```

### Windows 11 amd64

.NET Framework C# compiler and installed Codex. No Go installation is needed.
In PowerShell, in a new checkout:
