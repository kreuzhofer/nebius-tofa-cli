# GLM Flash and Kimi with a doubled coding deadline

This experiment repeats the desktop-engine baseline with the coding request and
whole-turn deadlines increased from 180 to **360 seconds**. The evaluator exposes
this as `--coding-timeout 360`; its default and historical manifest remain 180.
The outer coding-process wait is 420 seconds, allowing startup and cancellation
cleanup. Guardian request/review and turn limits remain 90 and 120 seconds;
request size, response size, output-token limits and the workload are unchanged.
Normal `./tofa` launches are unaffected.

Each model first passed a full matching controlled-provider qualification. Live
runs use the pinned desktop engine, the saved launcher login read-only, synthetic
workspaces and GLM 5.3 Flash as Guardian. The workload remains three coding
sessions with two turns and a relaunch per session, plus three Guardian allow/deny
pairs. A lane stops at its first failed case; later cases are unattempted, not
counted as passing. The live models run sequentially with no automatic retries.
These are headless desktop-engine tests, not Electron UI or standalone CLI tests.

The effective manifest has a separate campaign name and fingerprint, so results
cannot be merged with the 180-second baseline as identical conditions. The
[freeze](evidence/desktop-360s-2026-09-29/freeze.json) and
[source patch](evidence/desktop-360s-2026-09-29/source.patch) identify the immutable
`.qualification/desktop-360s-2026-09-29` capsule. Earlier reports remain unchanged.

## GLM 5.3 Flash

The [live report](evidence/desktop-360s-2026-09-29/glm-flash-repeat.json) did not pass
the full baseline. Its first session passed both the initial and resumed turns
at **339.011 and 250.345 seconds**, with correct numeric artifacts, successful
tools and continued conversation. These valid turns exceeded the old 180-second
budget, demonstrating that the old budget could reject otherwise passing work.

The second session failed its initial turn at **165.587 seconds**, without a
timeout. The turn completed, its one tool succeeded, streaming and tool-result
continuation worked, and the input stayed unchanged, but `summary.json` was
**missing** from the required workspace. Its second turn and the entire third
session were unattempted. Extra time did not solve this distinct artifact failure;
the retained sanitized evidence establishes the missing output, not the model's
internal reasoning or where else it may have attempted to write.

The first independent Guardian allow case also failed: no response headers
arrived before the unchanged **90-second native review deadline**. The requested
action did not execute, and five later Guardian cases were unattempted. Earlier
passing Guardian runs remain valid; this run does not erase them.

The run also reports `normal_settings_preserved: false` and `settings_changed`.
The evaluator detected a change among watched normal settings during the run;
`~/.codex/config.toml` had a modification time of 15:01:45 UTC. The evaluation
code did not write that file, and the recorded scratch credential checks passed.
The change's origin is not established by these observations. This run therefore
cannot establish complete settings preservation, regardless of the case results.
The report retains that failure rather than masking it.

## Kimi

The [live report](evidence/desktop-360s-2026-09-29/kimi-repeat.json) is **inconclusive
for a full model verdict**. Session 1 passed both turns at **150.934 and 108.930
seconds**, with correct artifacts and continuation. Session 2's first turn also
passed at **231.838 seconds**, exceeding the old deadline.

The next desktop launcher invocation exited with code 1 before producing a turn
result or a request observation. This is a startup/infrastructure interruption,
not evidence that the model failed the resumed task. The existing evaluator
then indexed a missing `same_session` field in its fallback failure result,
raising `KeyError` and abandoning the independent Guardian lane. The exact
launcher error cannot be recovered: that version discarded launcher stderr,
and its disposable scratch directory was cleaned. No Guardian requests or
third-session turns were attempted for Kimi.

A regression using the same successful-first-turn/failed-relaunch result pattern
reproduced `KeyError: same_session`. The small [post-run fix](evidence/desktop-360s-2026-09-29/post-run-launch-failure.patch)
uses `false` for an absent session confirmation, recording a failed case so the
independent lane can continue. Its test passes. This fix is **not** retroactively
included in the frozen live capsule or used to rewrite the interrupted report.

Kimi also reports `settings_changed`. The normal Codex config continued changing
after the paid runs (mtime observed at 15:12:53 UTC); the source of those changes
was not established. The launcher config and watched auth-file modification
times were older, and no credential mutation was performed by this work. The
concurrent repository rename did not edit normal user settings and left the
frozen capsule intact. Neither run can establish normal-settings preservation.

## What the doubled deadline establishes

Both models produced valid turns beyond 180 seconds in this run. Therefore the
old timeout alone was insufficient to classify those turns as incompatible.
Flash still failed the full coding baseline because a later completed turn left
the required file missing. Kimi has no completed full-baseline verdict from this
rerun because its second-session relaunch and the evaluator's error handling
interrupted it. No support records were changed. The observations do not identify
provider-internal latency causes or prove that still-longer deadlines would make
either model consistently pass.

## Accounting and validation

Across these two live invocations there were **21 paid requests, 20 with usage**,
plus **two synthetic observations**. Observed usage totals **187,934 input / 3,379
output tokens**. The known estimated subtotal is **USD 0.30156735**; total cost is
unknown because Flash's cancelled Guardian request has no usage. Exact refreshed
rates and role accounting are retained in the reports and [accounting record](evidence/desktop-360s-2026-09-29/accounting.json).
These are estimates from usage, not billing totals, and exclude earlier runs.

Both models passed matching full controlled qualifications at 360 seconds before
paid inference. The deadline tests failed before the implementation and passed
afterward, verifying the observer, actual engine turn deadline, outer wait and
manifest identity without a six-minute test sleep. Observer tests passed 13/13;
evaluation-command tests passed 34/34. The full desktop evaluator suite passed
19/20: one existing report-rebuild test's initial controlled invocation failed,
then the isolated test passed with retained evidence (59.249 seconds). The
initial temporary failure report was not retained, so that transient failure's
cause is unknown; it is not reported as a clean first-pass suite. The post-run
failed-relaunch regression and both file-diagnostic tests also pass. [Validation record](evidence/desktop-360s-2026-09-29/validation.json).

Some controlled regression checks overlapped Flash's initial provider waits.
Timings include provider wait, transport, adapter and local overhead. Only
sanitized statuses, timings, counts, numeric workload fields and usage are
retained; no raw prompts, model prose, tool output or credentials are published.
