## Windows live lifecycle and limits

The normal-account agent driver used a real PTY and the published PowerShell
installer/assets in new disposable state. It completed first-use authentication
before app selection in the same invocation, verified the actual target client's
version, repeated installation, and checked discovery from a fresh process.
Preserve-uninstall waited for the asynchronous helper. Reinstall used identical
candidate bytes and reused the saved login without credential entry. Final purge
removed the disposable installation, configuration, PATH entries and native vault
references. Every reported stage and preservation/cleanup assertion passed.

Each live phase checked two coding turns, streamed responses, successful tool
execution, independently verified JSON output, and continuation of the same
conversation. Native Guardian allow executed the controlled marker command;
native Guardian deny prevented execution. Coding and Guardian inference were
live; approval main-model proposals were synthetic. The separate installed-client
fixture used a loopback synthetic provider and incurred no paid inference.

Windows used **12 + 11 = 23 of 24 permitted paid upstream requests**. Each phase
had a 12-request limit, 4,096 output tokens/request, 1 MiB request body, 8 MiB
response and 256 KiB SSE event limits. Coding turn/request deadlines were 180
seconds; approval turns were bounded at 120 seconds and native Guardian/request
deadlines at 90 seconds. No automatic harness retries or model substitution were
enabled. These are operational bounds, not a currency cap or broad model-safety
qualification. Mac final acceptance used 16 requests; its retained earlier
runner-failure attempt used another 9, as reported on October 1.

## Sandbox diagnosis and retained failures

The earlier suggested sandbox command was unavailable in the installed client.
Direct app-server readiness and command execution established that Codex 0.160.0
already had a working native sandbox in its normal home. The same client with a
[fresh private home reported `updateRequired`](evidence/rc14-cli-2026-10-02/sandbox-private-home.json),
while the [existing home reported `ready` and passed a restricted command probe](evidence/rc14-cli-2026-10-02/sandbox-native-home.json).
The harness's forced unelevated mode failed; selecting elevated mode in a fresh
home alone timed out. These were installed-client prerequisites, not provider
or model failures, and consumed no live Windows inference.

An attempted disposable sandbox setup produced a UAC prompt. Automatic computer-use
approval review rejected a coordinate click because it could not verify the
prompt target/permission scope. Setup ended with Windows cancellation code 1223;
no new sandbox setup was approved or needed for the final route. The earlier
pending UAC request is superseded.

The runner now has an explicit `TOFA_NATIVE_WINDOWS_CODEX_HOME` opt-in to reuse
the already initialized sandbox. It keeps workspaces, application data, temporary
files, logs and database state private, supplies launcher settings as runtime CLI
overrides, disables unrelated plugins/hooks/MCP/memory/project instructions for
the test, and checks ordinary config/auth preservation. It does not rewrite the
normal configuration or copy its authentication. Default runner behavior is
unchanged; the opt-in requires Python 3.11+ and an already ready native sandbox.

The native sandbox then executed tools, but its output file inherited an
`OWNER RIGHTS` ACL that prevented the initiating account from reading it. A
read-only ACL inspection reproduced this ownership distinction. The runner adds
an inheritable Modify ACE for the current user only on the newly owned test
workspace. It grants no broader principal access. A subsequent fixture exposed
incorrectly quoted dotted override keys; correcting those keys restored the
intended native approval policy. The complete installed-client coding/allow/deny
fixture then passed, including config/auth preservation and session cleanup.
Raw failure logs remain private; published evidence contains fixed observations,
numeric results and sanitized categories, without SIDs or private conversations.

The guest retains the explicitly requested CurrentUser `RemoteSigned` policy and
the previously diagnosed IPv4 MTU 1200. TLS verification remained enabled. These
prerequisites and the October 1 failures are retained in the
[onboarding report](onboarding-74-2026-10-01.md) and [earlier CLI report](rc14-cli-2026-10-01.md).
